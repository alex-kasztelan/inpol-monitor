# Inpol Monitor

Автоматизированная система мониторинга польского государственного портала (inpol.mazowieckie.pl)

**Языки:** [English](README.md) | [Русский](README.ru.md) | [Українська](README.ua.md) | [Polski](README.pl.md)

## Обзор

Inpol Monitor отслеживает иммиграционные дела на нескольких учетных записях, чтобы выявлять любые изменения статусов, документов, вопросов или сроков — и пользователь никогда не пропустит важное обновление.

## Что делает система

- **Аутентификация**: Вход на портал Inpol с несколькими учетными записями (последовательная аутентификация с обработкой CSRF)
- **Извлечение данных**: Получение данных по всем настроенным делам
- **Хранение**: Сохранение всех исторических снимков в базу данных SQLite с неизменяемостью (только INSERT)
- **Обнаружение изменений**: Сравнение текущего состояния с предыдущим снимком, обнаружение 7 типов изменений:
  - Изменения статуса
  - Новые/удаленные документы
  - Изменения дат (сроки решения, даты подачи, updated_at)
  - Изменения вопросов (включая поля уровня вопроса)
  - События таймлайна
- **Уведомления**: Отправка подробных отчетов об изменениях в Telegram (поддержка нескольких пользователей) с резервной отправкой по электронной почте, если Telegram недоступен
- **Планировщик**: Автоматические проверки в 8:00, 12:30 и 18:00 по польскому времени (CET/CEST) через Планировщик задач Windows
- **Веб-интерфейс**: Flask-приложение для просмотра и сравнения исторических снимков дел с подсветкой изменений на уровне полей

## Начало работы

### Предварительные требования

- Python 3.11+
- Windows 11 (для Планировщика задач) или любая ОС для разработки

### Быстрая установка

1. **Клонирование и настройка**
   ```bash
   git clone https://github.com/your-repo/inpol-monitor.git
   cd inpol-monitor
   python -m venv .venv
   .venv\Scripts\activate  # Windows
   # или ./venv/bin/activate  # Linux/macOS
   pip install -r requirements.txt
   ```

2. **Настройка окружения**
   ```bash
   cp .env.example .env
   # Отредактируйте .env с вашими настройками (язык, логирование, email)
   ```

3. **Загрузка учетных данных**
   ```bash
   cp credentials.json.example credentials.json
   # Отредактируйте credentials.json с вашими реальными учетными данными
   ```

4. **Запуск приложения**
   ```bash
   # Проверка аутентификации
   python check.py

   # Полный цикл мониторинга
   python -m src.orchestrator
   ```

### Конфигурация

#### Конфигурация .env
```
# Языковые настройки
LANGUAGE=en         # Язык веб-интерфейса (en, pl, ru, ua)
NOTIFICATION_LANGUAGE=en  # Язык уведомлений Telegram/email

# Портал
INPOL_BASE_URL=https://inpol.mazowieckie.pl

# Логирование JSON-ответов (для анализа API)
JSON_LOGGING_ENABLED=false

# Email-уведомления (резервный канал)
EMAIL_ENABLED=false
SMTP_SERVER=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=your-username
SMTP_PASSWORD=your-password
EMAIL_FROM=noreply@example.com
EMAIL_TO=your-email@example.com
```

## Использование

### Ручные проверки
```cmd
# Быстрая проверка аутентификации
python check.py

# Полный цикл мониторинга (с логированием)
python -m src.orchestrator
```

### Автоматические проверки (Планировщик задач Windows)

Откройте PowerShell **от имени администратора** из каталога проекта:

```powershell
$SCRIPT = Join-Path (Get-Location) "run_check.cmd"
$TASK_NAME = "Inpol Monitor"

schtasks /Create /TN $TASK_NAME /TR $SCRIPT /SC DAILY /ST 08:00 /F /RL HIGHEST
schtasks /Create /TN "$TASK_NAME\Noon Check" /TR $SCRIPT /SC DAILY /ST 12:30 /F /RL HIGHEST
schtasks /Create /TN "$TASK_NAME\Evening Check" /TR $SCRIPT /SC DAILY /ST 18:00 /F /RL HIGHEST
```

Проверка и ручной запуск:

```cmd
schtasks /Query /TN "Inpol Monitor"
schtasks /Run /TN "Inpol Monitor"
```

Полное руководство по настройке, управлению и удалению см. в [SCHEDULING.md](SCHEDULING.md).

### Веб-интерфейс

1. **Запустите Flask-приложение** из корня проекта:
   ```bash
   python -m src.web.__main__
   ```

2. **Откройте** `http://localhost:5000` в браузере и войдите с учетными данными веб-интерфейса.

3. **Возможности**:
   - Вход с учетными данными
   - Просмотр всех снимков с фильтрами (дело, аккаунт, эндпоинт, диапазон дат)
   - Сравнение двух снимков бок о бок
   - Отображение всех 7 полей вопроса с подсветкой изменений на уровне полей
   - Поддержка переводов (EN, PL, UA, RU)

## Возможности

### Основные требования
- [x] **AUTH-01**: Аутентификация с несколькими учетными записями через последовательный поток с обработкой CSRF
- [x] **AUTH-02**: Безопасное хранение учетных данных через .env и credentials.json
- [x] **DATA-01**: Извлечение данных по всем настроенным делам
- [x] **DATA-02**: Извлечение статусов, дат, документов, сроков с поддержкой i18n
- [x] **STORE-01**: Сохранение снимков в SQLite с меткой времени
- [x] **STORE-02**: Неизменяемость (только INSERT, полное сохранение истории)
- [x] **STORE-03**: Запрос снимков по case_id (глобально уникальный)
- [x] **DETECT-01**: Сравнение текущего состояния с предыдущим снимком
- [x] **DETECT-02**: Обнаружение 7 типов изменений (статус, документы, даты, вопросы)
- [x] **NOTIFY-01**: Отправка подробных отчетов об изменениях в Telegram
- [x] **NOTIFY-02**: Включение ID дела и конкретных изменений в уведомления
- [x] **SCHED-01**: Запуск в 8:00, 12:30, 18:00 по польскому времени
- [x] **SCHED-02**: Интеграция с Планировщиком задач Windows
- [x] **SCHED-03**: Ручной запуск через CLI
- [x] **ERROR-01**: Отправка уведомлений об ошибках при сбоях

### Фаза 12: Расширенное сравнение вопросов (завершена)
- **Сравнение на уровне полей**: Обнаружение изменений отдельных полей (title, status, status_label, body, sentTime, answer, responseTime) внутри вопросов
- **Отображение 7 полей вопроса**: Показ всех полей вопроса в представлении сравнения
- **Локализация**: Переведенные status_label через `Cases.Question.Statuses`, title через `Cases.Question.Titles`
- **Подсветка изменений**: Визуальное выделение измененных полей в интерфейсе

### Архитектура

1. **Слой аутентификации**: Последовательная аутентификация учетных записей с обработкой CSRF и управлением сессиями
2. **Слой извлечения**: Парсинг HTML с beautifulsoup4, обработка JSON-ответов API
3. **Слой хранения**: Репозиторий SQLite с INSERT-only хранением снимков
4. **Слой обнаружения**: Strategy pattern для 7 типов изменений, сравнение на уровне полей вопроса
5. **Слой уведомлений**: Batch-then-notify с Telegram (поддержка нескольких пользователей) и email-резервом
6. **Веб-слой**: Flask-приложение с аутентификацией, фильтрацией снимков, представлением сравнения

- **Тесты**: 162 теста проходят (покрытие 83%)

## Безопасность

- **Учетные данные**: Хранятся в зашифрованном credentials.json (пользователи должны защищать свои файлы)
- **HTML-инъекции**: Исправлено в email-уведомлениях (все контролируемые пользователем значения экранированы)
- **HTTPS**: Используется HTTPS для всех подключений к порталу
- **Безопасность сессий**: CSRF-токены, безопасное управление сессиями
- **Доступ к файлам**: Разрешения файла базы данных SQLite (чтение/запись только для пользователя приложения)

## Вклад в проект

1. **Фаза планирования**: Обсуждение → Исследование → Определение требований → Создание дорожной карты → Планирование фазы
2. **Реализация**: Выполнение планов с атомарными коммитами, циклами верификации

### Правила коммитов

- **Коммиты фаз**: Включайте номер фазы в сообщение коммита (`feat(12-01): ...`)
- **Co-authored-by**: Всегда добавляйте `Co-Authored-By: Claude Code <noreply@anthropic.com>`
- **Атомарные коммиты**: Каждый коммит должен содержать одно логическое изменение
- **Конвенция**: Conventional commits с типом:область описание

### Стандарты кода

- **Python**: Лимит строки 88 символов, форматирование black, pytest
- **Документация**: Markdown с согласованной иерархией заголовков
- **Тестирование**: Разработка через тестирование (TDD) для новых функций
