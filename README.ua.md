Автоматизована система моніторингу польського державного порталу (inpol.mazowieckie.pl)

## Огляд

Inpol Monitor відстежує імміграційні справи на кількох облікових записах, щоб виявляти будь-які зміни статусів, документів, питань або термінів — і користувач ніколи не пропустить важливе оновлення.

## Що робить система

- **Автентифікація**: Вхід на портал Inpol з кількома обліковими записами (послідовна автентифікація з обробкою CSRF)
- **Витяг даних**: Отримання даних по всіх налаштованих справах
- **Зберігання**: Збереження всіх історичних знімків у базу даних SQLite з незмінюваністю (тільки INSERT)
- **Виявлення змін**: Порівняння поточного стану з попереднім знімком, виявлення 7 типів змін:
  - Зміни статусу
  - Нові/видалені документи
  - Зміни дат (строки рішення, дати подачі, updated_at)
  - Зміни питань (включно з полями рівня питання)
  - Події таймлайну
- **Сповіщення**: Надсилання детальних звітів про зміни в Telegram (підтримка кількох користувачів) з резервною відправкою на електронну пошту, якщо Telegram недоступний
- **Планувальник**: Автоматичні перевірки о 8:00, 12:30 та 18:00 за польським часом (CET/CEST) через Планувальник завдань Windows
- **Веб-інтерфейс**: Flask-додаток для перегляду та порівняння історичних знімків справ з підсвіткою змін на рівні полів

## Початок роботи

### Попередні вимоги

- Python 3.11+
- Windows 11 (для Планувальника завдань) або будь-яка ОС для розробки

### Швидка встановлення

1. **Клонування та налаштування**
   ```bash
   git clone https://github.com/your-repo/inpol-monitor.git
   cd inpol-monitor
   python -m venv .venv
   .venv\Scripts\activate  # Windows
   # або ./venv/bin/activate  # Linux/macOS
   pip install -r requirements.txt
   ```

2. **Налаштування середовища**
   ```bash
   cp .env.example .env
   # Відредагуйте .env з вашими налаштуваннями (мова, логування, email)
   ```

3. **Завантаження облікових даних**
   ```bash
   cp credentials.json.example credentials.json
   # Відредагуйте credentials.json з вашими реальними обліковими даними
   ```

4. **Запуск додатку**
   ```bash
   # Перевірка автентифікації
   python check.py

   # Повний цикл моніторингу
   python -m src.orchestrator
   ```

### Конфігурація

#### Конфігурація .env
```
# Налаштування мови
LANGUAGE=en         # Мова веб-інтерфейсу (en, pl, ru, ua)
NOTIFICATION_LANGUAGE=en  # Мова сповіщень Telegram/email

# Портал
INPOL_BASE_URL=https://inpol.mazowieckie.pl

# Логування JSON-відповідей (для аналізу API)
JSON_LOGGING_ENABLED=false

# Email-сповіщення (резервний канал)
EMAIL_ENABLED=false
SMTP_SERVER=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=your-username
SMTP_PASSWORD=your-password
EMAIL_FROM=noreply@example.com
EMAIL_TO=your-email@example.com
```

#### Конфігурація credentials.json
```json
{
  "AccountName1": {
    "username": "email@example.com",
    "password": "secure-password",
    "case_ids": ["CASE-001", "CASE-002", "CASE-003"]
  },
  "AccountName2": {
    "username": "email2@example.com",
    "password": "another-password",
    "case_ids": ["CASE-004", "CASE-005"]
  }
}
```

## Використання

### Ручні перевірки
```cmd
# Швидка перевірка автентифікації
python check.py

# Повний цикл моніторингу (з логуванням)
python -m src.orchestrator
```

### Автоматичні перевірки (Планувальник завдань Windows)

Відкрийте PowerShell **від імені адміністратора** з каталогу проєкту:

```powershell
$SCRIPT = Join-Path (Get-Location) "run_check.cmd"
$TASK_NAME = "Inpol Monitor"

schtasks /Create /TN $TASK_NAME /TR $SCRIPT /SC DAILY /ST 08:00 /F /RL HIGHEST
schtasks /Create /TN "$TASK_NAME\Noon Check" /TR $SCRIPT /SC DAILY /ST 12:30 /F /RL HIGHEST
schtasks /Create /TN "$TASK_NAME\Evening Check" /TR $SCRIPT /SC DAILY /ST 18:00 /F /RL HIGHEST
```

Перевірка та ручний запуск:

```cmd
schtasks /Query /TN "Inpol Monitor"
schtasks /Run /TN "Inpol Monitor"
```

Повний посібник з налаштування, керування та видалення дивіться в [SCHEDULING.md](SCHEDULING.md).

### Веб-інтерфейс

1. **Запустіть Flask-додаток** з кореня проєкту:
   ```bash
   python -m src.web.__main__
   ```

2. **Відкрийте** `http://localhost:5000` у браузері та увійдіть з обліковими даними веб-інтерфейсу.

3. **Можливості**:
   - Вхід з обліковими даними
   - Перегляд усіх знімків з фільтрами (справа, обліковий запис, ендпоінт, діапазон дат)
   - Порівняння двох знімків бок о бок
   - Відображення всіх 7 полів питання з підсвіткою змін на рівні полів
   - Підтримка перекладів (EN, PL, UA, RU)

### Архітектура

1. **Шар автентифікації**: Послідовна автентифікація облікових записів з обробкою CSRF та керуванням сесіями
2. **Шар витягу**: Парсинг HTML з beautifulsoup4, обробка JSON-відповідей API
3. **Шар зберігання**: Репозиторій SQLite з INSERT-only зберіганням знімків
4. **Шар виявлення**: Strategy pattern для 7 типів змін, порівняння на рівні полів питання
5. **Шар сповіщень**: Batch-then-notify з Telegram (підтримка кількох користувачів) та email-резервом
6. **Веб-шар**: Flask-додаток з автентифікацією, фільтрацією знімків, представленням порівняння

> 📊 **Візуальна архітектура**: Див. [Діаграми архітектури](docs/ua/architecture/ARCHITECTURE.md) та [Взаємодії системи](docs/ua/system-interactions/SYSTEM_INTERACTIONS.md) для повних діаграм компонентів і послідовностей.

### Контроль якості

- **Тести**: 162 тести проходять (покриття 83%)
- **Рев'ю коду**: Рев'ю стандартної глибини, що покриває thread-прохід detector → notifier → email_notifier
- **Виправлення HTML-ін'єкції**: Усі контрольовані користувачем значення в email екрануються через `html.escape()`
- **Локалізація**: Підтримка 7 мовних ключів (en, pl, ru, ua)
- **Валідація**: Золоті файли, тести сценаріїв відмов
- **Документація**: README, SCHEDULING.md, PROJECT.md

## Відомі проблеми

- **Захист від ботів Akamai**: Авто-розв'язання JS-челленджу через meta-refresh (~2с на API-виклик)
- **Існуючий збій тесту**: `tests/planner/test_noti_format.py` (NameError: `status_id` не визначений) — не пов'язано з поточними змінами

## Безпека

- **Облікові дані**: Зберігаються у зашифрованому credentials.json (користувачі мають захищати свої файли)
- **HTML-ін'єкції**: Виправлено в email-сповіщеннях (усі контрольовані користувачем значення екрановані)
- **HTTPS**: Використовується HTTPS для всіх підключень до порталу
- **Безпека сесій**: CSRF-токени, безпечне керування сесіями
- **Доступ до файлів**: Розрішення файлу бази даних SQLite (читання/запис лише для користувача додатку)
